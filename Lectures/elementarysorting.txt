Elementary Sorting Algorithms

Note: all the sorting algorithms presented below are too slow and should
not be used in practice (except for Insertion Sort in specific
circumstances; see below).  We describe them only as an introduction to
sorting and because you need to know why you should *not* use them.


Bubble Sort

Bubble Sort works by comparing adjacent elements in the array and swapping
them if they are out of order.  By doing this repeatedly during a pass from
the beginning of the array to its end, the largest element "bubbles up" to
the end of the array.  The same process is then repeated during a second
pass to bubble up the second largest element, etc., until the whole array
is sorted.

Here is the code from page 100 of the Levitin textbook:

void bubble_sort(int array[], const int length) {
    for(int i = 0; i <= length - 2; i++) {
        for(int j = 0; j <= length - 2 - i; j++) {
            if(array[j + 1] < array[j]) {
                swap(array, j, j + 1);
            }
        }
    }
}

Here is an example showing how Bubble Sort works.  The variable i is used
to count the passes through the array.  The part of the array to the right
of the "|" symbol is the part of the array which is already sorted (the
size of this sorted part of the array is always equal to i).  We use a dash
"-" to indicate a swap:

                89 45 68 90 29 34 17 |

i = 0, j = 0    45-89 68 90 29 34 17 |
       j = 1    45 68-89 90 29 34 17 |
       j = 2    45 68 89 90 29 34 17 |
       j = 3    45 68 89 29-90 34 17 |
       j = 4    45 68 89 29 34-90 17 |
       j = 5    45 68 89 29 34 17-90 |    6 comparisons, 5 swaps

i = 1, j = 0    45 68 89 29 34 17 | 90
       j = 1    45 68 89 29 34 17 | 90
       j = 2    45 68 29-89 34 17 | 90
       j = 3    45 68 29 34-89 17 | 90
       j = 4    45 68 29 34 17-89 | 90    5 comparisons, 3 swaps

i = 2, j = 0    45 68 29 34 17 | 89 90
       j = 1    45 29-68 34 17 | 89 90
       j = 2    45 29 34-68 17 | 89 90
       j = 3    45 29 34 17-68 | 89 90    4 comparisons, 3 swaps

i = 3, j = 0    29-45 34 17 | 68 89 90
       j = 1    29 34-45 17 | 68 89 90
       j = 0    29 34 17-45 | 68 89 90    3 comparisons, 3 swaps

i = 4, j = 0    29 34 17 | 45 68 89 90
       j = 1    29 17-34 | 45 68 89 90    2 comparisons, 1 swap

i = 5, j = 0    17-29 | 34 45 68 89 90    1 comparison, 1 swap

In general Bubble Sort always makes n-1 + n-2 + ... + 1 = n(n-1)/2
comparisons.

The number of swaps depends on the values stored in the array.  In the best
case when the array is already sorted in increasing order, zero swaps
occur.  In the worst case when the array is already sorted in decreasing
order, there is one swap for each comparison, so n(n-1)/2 swaps.  In both
cases, we still need to make n(n-1)/2 comparisons so the number of swaps
does not make any difference for the order of growth.

Therefore for Bubble Sort we have:
best case:    Θ(n²)
worst case:   Θ(n²)
average case: Θ(n²)
overall:      Θ(n²)

Note: when looking at the best case, we look at the running time of Bubble
Sort when given as input only arrays which are already sorted in increasing
order, for various sizes of n.  Therefore, when looking at the running time
of Bubble Sort in the best case *only*, this running time is Θ(n²), not
just Ω(n²).

Similarly, when looking at the worst case, we look at the running time of
Bubble Sort when given as input only arrays which are already sorted in
decreasing order, for various sizes of n.  Therefore, when looking at the
running time of Bubble Sort in the worst case *only*, this running time is
Θ(n²), not just O(n²).

For the average case, we give as input to Bubble Sort arrays of various
sizes n which contain numbers in random order, neither already sorted in
increasing order nor sorted in decreasing order (or any order close to
that).

The overall case is then the analysis of the running time for *any* input.


Bubble Sort Optimized

The version of Bubble Sort above always makes n(n-1)/2 comparisons even
when the input array is already sorted, which is a waste of time.

To optimize Bubble Sort, we can notice that, at the end of a pass, all the
elements after the position of the last swap are guaranteed to be sorted
and do not need to be checked again in a subsequent pass.  For example:

                34 45 29 17 68 89 90 |

i = 0, j = 0    34 45 29 17 68 89 90 |
       j = 1    34 29-45 17 68 89 90 |
       j = 2    34 29 17-45 68 89 90 |
       j = 3    34 29 17 45 68 89 90 |
       j = 4    34 29 17 45 68 89 90 |
       j = 5    34 29 17 45 68 89 90 |    6 comparisons, 2 swaps

Here the last swap occurred at position 2 (when j = 2) between 17 and 45.
Therefore at the end of this pass we know that all the elements from
position 3 to the end of the array (45 68 89 90) are now sorted.  During
the next pass we then only need to sort the elements from position 0 to 2
(34 29 17), meaning that we can increase i from 0 directly to 4 (which is
7 - 2 - 1):

i = 4, j = 0    34 29 17 | 45 68 89 90
                ...

In essence we can skip three passes through the array since the position of
the last swap tells us that doing these three passes would be useless.

In general, if during a pass the last swap occurs at position s then all
the elements from position s+1 to the end of the array are sorted.  So the
variable i can be directly increased to be length-s-1 for the next pass:

void bubble_sort_opt(int array[], const int length) {
    for(int i = 0; i <= length - 2;) {
        int s = 0;
        for(int j = 0; j <= length - 2 - i; j++) {
            if(array[j + 1] < array[j]) {
                swap(array, j, j + 1);
                s = j;
            }
        }
        i = length - s - 1;
    }
}

In fact at that point we can remove i and just keep track of how much of
the array is still unsorted, using s only (and optimizing j a little):

void bubble_sort_opt(int array[], const int length) {
    int unsorted = length;
    while(unsorted > 0) {
        int s = 0;
        for(int j = 1; j < unsorted; j++) {
            if(array[j] < array[j - 1]) {
                swap(array, j - 1, j);
                s = j;
            }
        }
        unsorted = s;
    }
}

If the input array is already sorted in increasing order then no swap
occurs during the first pass, the variable s is then 0, so the variable
unsorted immediately becomes zero and the outer loop stops without doing
a second pass.  Therefore in the best case the optimized Bubble Sort
algorithm always takes exactly linear time.

In the worst case, the optimization described above has no effect and so the
running time remains Θ(n²).

For the average case, in practice the optimization described above
decreases the number of comparisons (the number of swaps always remains the
same) but not by more than a linear amount, so, while smaller, that number
of comparisons remains Θ(n²).

Therefore for Bubble Sort Optimized we have:
best case:    Θ(n)
worst case:   Θ(n²)
average case: Θ(n²)
overall:      O(n²) (and also Ω(n), which we don't really care about)

Since the best case and worst case have different orders of growth, there
is no Θ overall for this optimized Bubble Sort.


Selection Sort

As we have seen before, Selection Sort finds the smallest element in the
array and swaps it with the element at the front of the array (if the
smallest element is not already there).  Then the whole process is repeated
on the (unsorted) rest of the array to find and place the second smallest
element in second position, etc.  Each pass i finds the i-th smallest
element and moves it to position i.

Here is the iterative version of the code:

void selection_sort(int array[], const int length) {
    for(int i = 0; i < length - 1; i++) {
        int min_j = i;
        for(int j = i + 1; j < length; j++) {
            if(array[j] < array[min_j]) {
                min_j = j;
            }
        }
        if(min_j != i) {
            swap(array, i, min_j);
        }
    }
}

Here is an example showing how Selection Sort works.  The variable i is
used to count the passes through the array.  The part of the array to the
left of the "|" symbol is the part of the array which is already sorted
(the size of this sorted part of the array is always equal to i).  We use
the symbol "<" to indicate the current smallest element (on the left of the
symbol):

                | 89 45 68 90 29 34 17

i = 0, j = 1    | 89 45<68 90 29 34 17
       j = 2    | 89 45<68 90 29 34 17
       j = 3    | 89 45<68 90 29 34 17
       j = 4    | 89 45 68 90 29<34 17
       j = 5    | 89 45 68 90 29<34 17
       j = 6    | 89 45 68 90 29 34 17<
       swap     | 17 45 68 90 29 34 89    6 comparisons, 1 swap

i = 1, j = 2    17 | 45<68 90 29 34 89
       j = 3    17 | 45<68 90 29 34 89
       j = 4    17 | 45 68 90 29<34 89
       j = 5    17 | 45 68 90 29<34 89
       j = 6    17 | 45 68 90 29<34 89
       swap     17 | 29 68 90 45 34 89    5 comparisons, 1 swap

i = 2, j = 3    17 29 | 68<90 45 34 89
       j = 4    17 29 | 68 90 45<34 89
       j = 5    17 29 | 68 90 45 34<89
       j = 6    17 29 | 68 90 45 34<89
       swap     17 29 | 34 90 45 68 89    4 comparisons, 1 swap

i = 3, j = 4    17 29 34 | 90 45<68 89
       j = 5    17 29 34 | 90 45<68 89
       j = 6    17 29 34 | 90 45<68 89
       swap     17 29 34 | 45 90 68 89    3 comparisons, 1 swap

i = 4, j = 5    17 29 34 45 | 90 68<89
       j = 6    17 29 34 45 | 90 68<89
       swap     17 29 34 45 | 68 90 89    2 comparisons, 1 swap

i = 5, j = 6    17 29 34 45 68 | 90 89<
       swap     17 29 34 45 68 | 89 90    1 comparison, 1 swap

In general Selection Sort always makes n-1 + n-2 + ... + 1 = n(n-1)/2
comparisons.

Note that the number of swaps for Selection Sort is much smaller than for
Bubble Sort, since we do at most one swap per pass (we make zero swap
during a pass when the current smallest element is already in position i).

The best case is when the array is already sorted and so no swap is
required, the worst case is when a swap is required on every iteration of
the outer loop.  In both cases, we still need to make n(n-1)/2 comparisons
so the number of swaps does not make any difference for the order of
growth.

Therefore for Selection Sort we have:
best case:    Θ(n²)
worst case:   Θ(n²)
average case: Θ(n²)
overall:      Θ(n²)

The recursive version of Selection Sort has exactly the same running time.


Insertion Sort

Insertion Sort works by taking the first element in the unsorted part of
the array and inserting it at the correct position in the part of the array
which has already been sorted:

void insertion_sort(int array[], const int length) {
    for(int i = 1; i < length; i++) {
        int j, current = array[i];
        for(j = i - 1; j >= 0 && array[j] > current; j--) {
            array[j + 1] = array[j];
        }
        array[j + 1] = current;
    }
}

Here is an example showing how Insertion Sort works.  The variable i is
used to count the passes through the array.  The part of the array to the
left of the "|" symbol is the part of the array which is already sorted
(the size of this sorted part of the array is always equal to i, until we
insert the new element in the sorted part).  We use the symbol ">" to
indicate a shift (copy) of a number by one position towards the end of the
array:

                89 | 45 68 90 29 34 17

current = 45
i = 1, j = 0    89>| 89 68 90 29 34 17
       insert   45 89 | 68 90 29 34 17    1 comparison, 1 shift

current = 68
i = 2, j = 1    45 89>| 89 90 29 34 17
       j = 0    45 89 | 89 90 29 34 17
       insert   45 68 89 | 90 29 34 17    2 comparisons, 1 shift

current = 90
i = 3, j = 2    45 68 89 | 90 29 34 17
       insert   45 68 89 90 | 29 34 17    1 comparison, 0 shift

current = 29
i = 4, j = 3    45 68 89 90>| 90 34 17
       j = 2    45 68 89>89 | 90 34 17
       j = 1    45 68>68 89 | 90 34 17
       j = 0    45>45 68 89 | 90 34 17
       insert   29 45 68 89 90 | 34 17    4 comparisons, 4 shifts

current = 34
i = 5, j = 4    29 45 68 89 90>| 90 17
       j = 3    29 45 68 89>89 | 90 17
       j = 2    29 45 68>68 89 | 90 17
       j = 1    29 45>45 68 89 | 90 17
       j = 0    29 45 45 68 89 | 90 17
       insert   29 34 45 68 89 90 | 17    5 comparisons, 4 shifts

current = 17
i = 6, j = 5    29 34 45 68 89 90>| 90
       j = 4    29 34 45 68 89>89 | 90
       j = 3    29 34 45 68>68 89 | 90
       j = 2    29 34 45>45 68 89 | 90
       j = 1    29 34>34 45 68 89 | 90
       j = 0    29>29 34 45 68 89 | 90
       insert   17 29 34 45 68 89 90 |    6 comparisons, 6 shifts

Note that Insertion Sort does not swap elements, instead it shifts elements
in the sorted part of the array by one position at a time towards the end
of the array to make room for the new element that we currently want to
insert.

In the best case when the array is already sorted in increasing order, zero
shifts occur and only one comparison is required per pass (see the case i=3
above for an example of such a pass).  Insertion Sort then takes linear
time.

In the worst case when the array is already sorted in decreasing order,
there is one shift for every comparison and i comparisons per pass (see the
case i=6 above for an example of such a pass) for a total number of
comparisons (and shifts) equal to 1 + ... + n-2 + n-1 = n(n-1)/2.

In the average case Insertion Sort needs to shift half of the sorted array
to make room for the element we want to insert, so the number of comparisons
and shifts is i/2.  This gives a total number of comparisons (and shifts)
equal to 1/2 + ... + (n-2)/ + (n-1)/2 = n(n-1)/4, which still gives a
quadratic running time.

Therefore for Insertion Sort we have:
best case:    Θ(n)
worst case:   Θ(n²)
average case: Θ(n²)
overall:      O(n²)


So we have the following results:

         BubbleSort  BubbleSortOpt  SelectionSort  InsertionSort
best:    Θ(n²)       Θ(n)           Θ(n²)          Θ(n) 
worst:   Θ(n²)       Θ(n²)          Θ(n²)          Θ(n²)
average: Θ(n²)       Θ(n²)          Θ(n²)          Θ(n²)
overall: Θ(n²)       O(n²)          Θ(n²)          O(n²)

From this it looks like Bubble Sort and Selection Sort have similar running
times, and so do Bubble Sort Optimized and Insertion Sort.


In Practice

We can time the different sorting algorithms on random input of increasing
sizes and we get the following results:

1) Bubble Sort Optimized is slightly better than Bubble Sort.
(In reality, optimizing j seems to help more than optimizing i using s...)

2) Both Bubble Sort and Bubble Sort Optimized are worse than Selection
Sort.  That's because Bubble Sort does many swaps per pass while Selection
Sort makes at most one swap per pass.  So, even though both Bubble Sort and
Selection Sort are Θ(n²) (and Bubble Sort Optimized is O(n²)), in practice
the constant factor for the n² term for Selection Sort is clearly smaller.

So NEVER use Bubble Sort!

3) Insertion Sort is the best of all.  There are two reasons for that.  One
reason is that shifting is faster than swapping (though Insertion Sort does
many more shifts than Selection Sort does swaps).  Another reason is that a
pass can be stopped early if the element we are currently trying to insert
is close to or at the position where it should be (see the case for i=3
above, for example).

On average Insertion Sort will need to shift only half the elements in the
sorted part of the array, while Selection Sort always has to keep going
until it reaches the end of the array.  This allows Insertion Sort to skip
many iterations of its inner loop.  Combined with the cheap cost of
shifting, this makes Insertion Sort the best algorithm.

So NEVER use Selection Sort!

Insertion Sort is still O(n²) though which is still not very good, so it
should not be used for big inputs.  For small inputs, Insertion Sort has a
very low constant factor for its n² term so it turns out to be quite fast.

In fact, for small inputs (and only small inputs), Insertion Sort if faster
than some of the better algorithms we will see later such as QuickSort, so
we will talk about Insertion Sort again in the future when dealing with
small inputs.
